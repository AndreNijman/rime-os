# Suites CI does not run, and why. One path, then the reason.
#
# check-suites-run-in-ci.sh fails if a suite is in neither a workflow nor this
# file, AND fails if a suite here starts being run by CI — so this list can
# only shrink. Everything below that is not a `-live` suite is DEBT, not a
# decision: it should be wired into a workflow and deleted from here.
#
# ── legitimately cannot run on a GitHub runner ──────────────────────────────
tests/test-rime-audio-live.sh        needs real audio hardware; -live by name
tests/test-rime-firewall-live.sh     loads nftables into the live kernel; needs CAP_NET_ADMIN
tests/test-rime-lid-live.sh          needs a real SW_LID device and a logind session
# firewall-ssh is here and not below because it is not headless-able at all:
# it is a DRIVER that loads the policy into ANOTHER host's live kernel over
# ssh, holds that ssh open across the load to prove the connection survived,
# and probes the target from off the machine. It requires --target HOST plus
# --yes-this-host-may-lose-its-network, and refuses outright if the target
# resolves to the machine it is running on. A runner is one ephemeral VM with
# no second host to un-network, and 127.0.0.1 is exactly the vantage point the
# suite's own header says would make the measurement meaningless.
tests/test-rime-firewall-ssh.sh      needs a SECOND machine, and refuses to target its own
# The encrypted-install suite does a REAL `bootc install` onto a REAL LUKS2
# volume on a loopback file. That needs root, ~25 GB of free disk and the
# 15.5 GB Rime OS image in root podman storage; a runner has none of them, and
# building the image inside the job would turn a five-minute check into a
# ninety-minute one. Its fast half — every refusal, the XKB-to-console keymap
# conversion and the character-level keyboard checks — is
# installer/test-installer-luks.sh, which pr-validation.yml DOES run. Like
# luks-boot and live-paths below, it runs the engine inside the installer's
# live-environment image (installer/live-env-engine), so that image must be
# built here too.
installer/test-installer-luks-live.sh  needs root, a loop device, the 15 GB image and the live-env image
# The keymap boot suite boots FIVE real guests off the shipped initramfs and
# types a passphrase on an emulated keyboard through QMP, to measure the one
# property no file-content assertion can stand in for: that a passphrase
# containing a character a non-`us` layout produces actually unlocks the volume
# at the boot prompt. It needs /dev/kvm, root podman, the 15.5 GB image and the
# rime-bootlab container. A GitHub runner has no nested virtualisation worth
# the name and the TCG fallback would take an hour per boot.
installer/test-installer-keymap-boot.sh  needs /dev/kvm, root podman and the 15 GB image
# The luks-boot suite does a REAL encrypted install (its own loopback file,
# root and cryptsetup, same as -live above) and then boots the WHOLE DISK
# under OVMF in the rime-bootlab container, types the passphrase through QMP
# and reads dracut's own "Switching root" line — the property neither -live
# nor the keymap-boot suite measures: that a disk this installer wrote
# actually boots through firmware, shim and GRUB into the real root. Needs
# root, a loop device, /dev/kvm, root podman, the 15 GB image and the
# rime-bootlab container; strictly more than either suite above.
installer/test-installer-luks-boot.sh  needs root, a loop device, /dev/kvm, the 15 GB image and the live-env image
# The live-paths suite is the UNENCRYPTED counterpart of luks-boot. It rigs a
# GPT with a Windows-shaped ESP and a data partition, installs Rime into the
# free one, and asserts the neighbour is byte-identical afterwards AND after
# Rime has booted once; then it runs a whole-disk network install onto a
# 12 GiB disk, which streams ~6.9 GB from the registry straight onto it. Needs
# root, a loop device, /dev/kvm, root podman, the 15.5 GB image, the
# installer's live-env image, ~40 GB on /var/lab-scratch and a route to
# ghcr.io. Its fast half is installer/test-installer.sh, which pr-validation.yml
# DOES run.
installer/test-installer-live-paths.sh  needs root, a loop device, /dev/kvm, the 15 GB image, the live-env image and network
